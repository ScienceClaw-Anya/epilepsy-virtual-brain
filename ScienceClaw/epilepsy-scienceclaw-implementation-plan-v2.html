From evidence to intervention

A research agent system for epilepsy surgery & stimulation.

An updated implementation plan built around ScienceClaw’s shared artifacts and need-driven coordination: discover usable evidence, construct and challenge virtual patients, compare feasible interventions, and improve future runs through offline validation.

01 / Start with an achievable research result

Build a trustworthy first loop.

Build an evidence-driven research system with bounded exploration and explicit validation gates. The first release should complete a reproducible literature-to-dataset-to-virtual-surgery loop, using scoped requests for missing information and a separate path for improving future releases.

Design decision in this revision: use the reference chain as a guide to responsibilities, then organize the system around shared artifacts and scoped needs. Combine seizure-network hypotheses with patient modeling, combine intervention reasoning under separate surgery/stimulation contracts, split simulation comparison from historical-outcome evaluation, and make improvement an explicit offline lifecycle.

DISCOVER

Know what evidence exists.

Find primary papers and associated data. Verify files, access conditions, modalities, intervention records, follow-up, and cohort overlap.

REPRODUCE

Recover a published baseline.

Rebuild a virtual-resection result with documented preprocessing, network definitions, intervention mapping, and numerical checks.

COMPARE

Explain a robust result.

Compare feasible alternatives across model uncertainty. Produce a review package showing evidence, tradeoffs, sensitivity, and unresolved gaps.

Research objective: identify interventions associated with sustained seizure freedom and preserved function. Keep simulated suppression, recorded acute response, and observed long-term outcome as separate result types.

Initial scope assumption: focal drug-resistant epilepsy in retrospective research. Resection, ablation, and disconnection are distinct intervention classes. Stimulation enters through a separate branch with device- and modality-specific modeling. Functional safety estimates require appropriate patient information; missing maps remain an explicit limitation.

What the first release delivers

  • A searchable evidence and dataset registry with verifiable source locations.
  • A reproducible case-preparation pipeline and versioned quality report.
  • A reproduced baseline, candidate virtual interventions, and sensitivity analysis.
  • A locked evaluation protocol and an inspectable result package.
  • A structured repair loop and an offline improvement-proposal record, initially exercised on development failures.

What determines scientific success

  • Predictions hold up on patients and recordings excluded from development.
  • Intervention rankings remain stable under plausible uncertainty, or instability is reported.
  • Every material claim points to measurements, calculations, and assumptions.
  • Alternative unperformed operations retain the label “model-based hypothesis.”

Reading guide: the main text explains the design. Expand the technical panels for module layouts, configuration examples, contracts, and test specifications. All new identifiers and configurations below are proposed interfaces.

02 / The recommended operating model

A shared research graph, with controlled case workflows.

Retain ScienceClaw’s artifact exchange and explicit requests for missing information. Add a rule-based controller that admits tasks, enforces patient and study boundaries, checks prerequisites, and records when evidence is sufficient to advance.

Recommended design: six research roles around a shared evidence and artifact store, backed by tested numerical workers. A deterministic study controller manages admissibility, versions, resource limits, and validation gates. Clinical and engineering review remains an explicit review activity.

Use three complementary loops.

DISCOVERY LOOP

Expand usable evidence.

Search papers and datasets, inspect access and contents, resolve missing methods, and record conflicting findings. New evidence produces explicit candidate updates.

CASE LOOP

Test patient hypotheses.

Prepare a case, fit and qualify models, generate feasible interventions, execute comparisons, and validate. Failed checks route repairs to the earliest affected stage.

IMPROVEMENT LOOP

Test system changes.

Analyze recorded failures and review feedback. Evaluate proposed changes offline and release a version for subsequent studies after review.

Scientific decisions remain explicit. Agents propose hypotheses, scenarios, or follow-up tasks with a concise rationale. The controller checks declared scope, prerequisites, and resource limits. Numerical workers calculate results. A gate records passed, failed, or indeterminate against a versioned criterion. Human review assesses the evidence package and its intended research use.

How this maps to the original ScienceClaw

Reuse ArtifactStore as the starting point for addressable results and lineage; NeedItem and ArtifactReactor for scoped discovery of missing information; the skill registry/executor for tool adapters; journals for durable events; and the dependency graph for per-case execution. Add explicit scientific contracts and admission checks at these integration points. [1]

For a frozen patient workflow, replace generic topic-driven tool selection with declared task templates. A literature query can remain exploratory. A patient simulation consumes exact artifact versions, model samples, intervention parameters, and acceptance checks.

03 / Specific changes and prerequisites

Fourteen changes to the framework.

Each item names the current integration point, intended change, and a meaningful acceptance check. Source links and line numbers refer to the pinned snapshot. Work-item IDs are stable cross-references; the delivery packages define implementation order and dependencies.

How to read the status: “Observed” refers to reviewed upstream behavior. “Proposed” describes implementation work. The plan does not treat a catalog entry, a successful process exit, a reviewer’s agreement, and a validated scientific result as equivalent.

SC-01 · P0

Enforce specialist capabilities consistently.

Current: _agent_execute_task(); run_deep_investigation(); ArtifactReactor.__init__().

Observed: the orchestrator supplies a skills field while selection reads other profile keys. Some unmatched configurations broaden selection to the full catalog.

  • Add AgentProfile with an explicit role, allowed tools, allowed artifact types, and workflow scope. Normalize legacy aliases at one boundary; reject conflicting declarations.
  • Pass the canonical profile through spawning, planning, reactor, and execution. Keep preferences separate from permissions.
  • Require explicit capabilities in patient workflows. Recheck them in the execution service even when the planner proposes a tool.
Done when: every entry path rejects a forbidden tool; an unknown tool or empty required capability set produces a configuration error; agents retain their role and scope after restart.
SC-02 · P0

Introduce scientific input and output contracts.

Current: SkillRegistry._parse_skill(); SkillExecutor._execute_script_skill().

Proposed: add explicit tool manifests declaring entry point, version, input/output schema, readiness, required resources, and data-access scope. Let new domain tools accept --input-json with structured references and expose --describe-schema.

  • Validate patient/run identity, coordinate frames, units, sampling, reference montage, atlas version, and array dimensions before execution.
  • Preserve arrays and nested structures. Large waveforms, meshes, and posterior samples live as checksum-verified files referenced by the manifest.
  • Give legacy scripts explicit adapters. Report invalid inputs without silently replacing scientific parameters with a generic query.
Done when: a three-contact configuration reaches the worker intact; mismatched coordinate frames are rejected; a placeholder or malformed output cannot become a validated computation.
SC-03 · P0

Unify execution and support durable jobs.

Current: execute_skill(); execute_experiment(); _run_agentic_computation().

Observed: the interactive computation branch can finish outside the normal artifact path, and a step-limit exit is wrapped as outer success. Generic executors also have different timeout and result conventions.

  • Add TaskSpec → ExecutionRecord → OutputArtifacts as the shared lifecycle. Wrap every execution path, including generated-code experiments.
  • Use separate statuses for queued, running, succeeded, failed, timed out, cancelled, and partial. A numerical-validity verdict is a separate field.
  • Store job IDs, heartbeats, attempts, logs, resource use, and output checksums. Submit long model jobs asynchronously, then collect their results.
  • Run scientific workers in pinned environments with scoped data mounts and declared network access. Prebuild dependencies for study runs.
Done when: interruption and resume preserve one execution identity; retries cannot duplicate committed results; a failed, timed-out, or exhausted computation cannot satisfy a scientific gate.
SC-04 · P0

Record actual computational lineage.

Current: Artifact / ArtifactStore; per-skill artifact chain.

Observed: the deep-investigation loop advances parentage to the previous skill. That sequential ancestry is useful history, but it is not a complete record of the inputs actually consumed.

  • Record consumed artifact IDs and file checksums explicitly. Use distinct UUIDs for study, cohort, case, run, and task; retain a human-readable topic as a label.
  • Store a canonical manifest covering scientific context, parents, tool/code version, environment digest, seed, configuration, and payload references. Verify it on load.
  • Enforce immutability in storage, including nested payloads. Corrections append new versions with explicit relationships.
  • Add an injectable storage root and a transactional index. Keep JSONL as an export/interchange format; use atomic job and artifact commits.
Done when: a combined inference result names all consumed inputs, a changed source invalidates affected descendants, and a restart can reconstruct the same run manifest.
SC-05 · P0

Make the reactor context-aware.

Current: _find_match(), _react_multi(), _transform(); NeedItem.

Observed: key overlap and some first-element extraction drive handoffs; multi-parent payloads can overwrite each other. Clinical research artifacts need stronger compatibility.

  • Route by declared schemas and context predicates. Enforce study/case scope; require a named cohort-aggregation task to combine subjects.
  • Replace flattened dictionaries with named input references, such as recording, electrode_map, connectome, and hypothesis.
  • Extend need signals with required schema/version, case scope, current stage, acceptance criteria, capability, and resource estimate. Register the new artifact types consistently in the schema and skill-domain maps.
  • Retain discovery-only key matching behind an explicit legacy policy. Clinical tasks require validated contracts.
  • Add transactional task claims with expiring leases, accepted-fulfillment records, and a context-complete idempotency key. Concurrent agents cannot commit duplicate fulfillment.
  • Same-role follow-ups pass through the controller’s task queue; preserve loop prevention and avoid infinite reactions. Configure need/branch limits explicitly and disclose truncation.
Done when: similarly named fields from two patients cannot trigger a joint model, and a need is marked fulfilled only after its declared acceptance checks pass.
SC-06 · P0

Preserve disagreements and required metadata.

Current: _prune(); _merge_conflict().

Observed: the pruning helper removes repeated field names; the reviewed conflict and redundancy dispatcher can route to timestamp-based merging. Preserve clinical research artifacts and replace these operations with explicit comparisons and version relationships.

  • Apply a retain-evidence policy to patient, measurement, model, intervention, and validation artifacts.
  • Represent alternatives with competes_with, supports, contradicts, and supersedes edges. An adjudication cites the resolving evidence and method.
  • Deduplicate identical content by hash while preserving source and cohort relationships. Keep required context fields in every derivative.
Done when: opposite findings survive synthesis, repeated units and case IDs remain present, and a superseded result retains its history and affected-dependency list.
SC-07 · P0

Make quality gates authoritative.

Current: completion handling; CompletionJudge; DependencyGraph.

  • Add domain transition checks for data readiness, model validation, intervention feasibility, robustness, and evidence release.
  • Reject missing dependency IDs before scheduling. Distinguish “all tasks terminal” from “all required tasks succeeded and validated.”
  • A failed gate returns structured reasons and repair tasks. Export diagnostic drafts with an incomplete status.
  • Require independent numerical reruns where specified. Keep language-model critique as an additional review channel.
Done when: missing dependencies, failed model checks, and unresolved critical evidence gaps prevent advancement; the user can inspect exactly which condition failed.
SC-08 · P0

Separate patient storage from publication.

Current: ArtifactStore.save() and _sync_to_infinite(); platform calls in the orchestrator, need broadcaster, and heartbeat loop.

  • Add a private research profile that disables outbound artifact, need, post, and comment synchronization by default. Enforce this centrally.
  • Give each artifact an access classification and permitted processing destinations. Pass only authorized content to configured model and data services.
  • Release a separately built, reviewed evidence export. Strip patient identifiers and restricted content according to the dataset agreement.
Done when: an offline integration test intercepts every outbound path and observes zero publication calls from a private case run, including metadata and needs.
SC-09 · P1

Ground claims and dataset links in source records.

Current: citation checks; clean_content(); literature skill adapters.

  • Verify identifiers against retrieved bibliographic records, then check whether the cited passage supports the associated claim.
  • Store source spans, extraction status, study design, population, endpoint, and linked accession/repository. Use one typed citation representation throughout.
  • Preserve unsupported claims as flagged review items. Record corrections and retractions when available.
  • Track study families and overlapping patient cohorts so multiple papers do not become multiple independent validations.
Done when: invented identifiers, irrelevant citations, inaccessible full text, and duplicated cohorts are distinguishable in both the registry and final report.
SC-10 · P1

Schedule research by decision value and cost.

Current: score_need(); heartbeat-driven scheduling.

Proposed: apply eligibility gates first, then rank useful tasks by their expected ability to resolve a decision-relevant uncertainty, adjusted for cost and dependencies. Begin with an inspectable heuristic; introduce probabilistic value-of-information estimates only when calibrated.

  • Prioritize missing prerequisites, discriminating model checks, and sensitivity analyses near unstable intervention rankings.
  • Use separate limits for language-model tokens, CPU/GPU time, storage, and concurrent jobs. Estimate before submission and reconcile actual use.
  • Acknowledge budget-limited results as incomplete. Cache by full scientific input, implementation, and environment versions.
Done when: a duplicate task reuses a valid result, an expired lease resumes safely, and an over-budget proposal stays unsubmitted with a visible reason.
SC-11 · P1

Build and certify the epilepsy tool set.

Current: executable discovery; NeuroKit demonstration wrapper; skill contribution conventions.

  • Create thin adapters for dataset inspection, case QC, network construction, baseline resection, model fitting, simulation, evaluation, and reporting.
  • Declare an explicit entry point instead of selecting an arbitrary first script. Mark tools as documentation-only, experimental, or validated for a named task/version.
  • Test actual signal and geometry operations with representative fixtures. Numerical behavior, input coverage, and known limits form the capability record.
Done when: required tools process representative inputs and satisfy their numerical contract; demonstration-only wrappers cannot enter the clinical-research execution set.
SC-12 · P1

Expose the domain workflow and evidence package.

New: domains/epilepsy/controller.py, needs_router.py, review.py, gates.py, __main__.py, and reporting.py. Integrate after the shared profile, execution, and artifact changes.

  • Provide explicit discover, inspect, prepare, reproduce, fit, compare, validate, resume, and export stages.
  • Use a frozen study configuration, saved cohort split, case manifests, model/candidate versions, and machine-readable gate history.
  • Export a readable report plus a reproducibility manifest containing evidence links, numerical outputs, uncertainties, exclusions, and limitations.
  • Emit and consume explicit gate, review, repair, and stale-artifact events. An accepted report and a validated numerical result have different statuses.
  • In domain mode, limit generic heartbeat activity to eligible discovery and job supervision; frozen patient tasks retain their declared models and parameters.
Done when: one command can resume an authorized study from saved state and regenerate its evidence package without repeating completed valid work.
SC-13 · P1

Make cross-run learning a proposal lifecycle.

Current: PrincipleExtractor; post-investigation principle extraction; journals and the knowledge graph. New: improvement.py and release_registry.py.

Proposed: convert recurring patterns into evidence-linked ImprovementProposals with exact changes, comparison protocols, development-data permissions, regression tests, independent review, and rollback. Keep inferred “principles” provisional until tested.

  • Record BenchmarkRun, ReviewDecision, and ReleaseRecord artifacts. Separate proposal authorship, benchmark execution, and promotion authority.
  • Freeze system, protocol, data, model, and intervention versions for active studies. Promote accepted changes to eligible future runs only.
  • Mark an evaluation cohort exposed if it informs a proposal; require fresh or properly separated evidence for a subsequent independent-generalization claim.
Done when: a proposal can be reproduced, accepted, rejected, or revised offline; the proposer cannot self-promote; active runs remain on their frozen release; rollback restores the prior accepted implementation.
SC-14 · P0

Separate simulation comparison from historical evaluation.

New: evaluation.py, outcome_vault.py, review.py, and prediction-freeze manifests. Integrate with the controller, artifact policies, and case/cohort split contracts.

  • Define two task types with distinct inputs and permissions: simulation robustness/comparison, and historical-outcome evaluation of delivered interventions.
  • Require a frozen method and prediction manifest before the evaluation service reveals postoperative masks, then outcomes. Handle truly presurgical clinical plans as a distinct input.
  • Store original outcome definitions, follow-up, missingness, patient-level metrics, and uncertainty. Record every label/mask reveal and any later exploratory analysis.
  • Give human reviewers structured acceptance, revision, or unsupported-conclusion decisions, with affected artifacts and repair checks.
Done when: fitting and strategy roles cannot read reserved labels; early reveal is rejected; delivered-surgery evaluation is reproducible; hypothetical alternatives remain labeled model-based; revision invalidates exactly the affected descendants.

P0 = prerequisite for trustworthy patient research. P1 = the first research workflow. These are proposed implementation priorities, not claims of completed patches.

04 / Six research roles, with clear service boundaries

Give agents scientific responsibilities.

Use six role specifications. Start the first research run with R1–R5; enable R6 when structured failure and review records exist. A role may have several scoped instances, but every instance has declared capabilities and a bounded task.

R1 / EVIDENCE & DATASET SCOUT

Find evidence the system can actually use.

Consumes
Study question, search protocol, source policy, and open evidence or acquisition needs.
Proposes and invokes
Logged literature search, source verification, data/code discovery, permitted sample inspection, and cohort-overlap analysis.
Produces
EvidenceClaims, DatasetCards, MethodCards, access records, and specific missing-data or method needs.
Acceptance
Source passages resolve; actual access and verified contents are separated from reported availability.
Boundary
Retrieved content cannot change system permissions. Restricted data are acquired only through permitted access paths.
R2 / CASE-CURATION AGENT

Build a trustworthy patient-case package.

Consumes
Verified dataset card, retrieval manifest, subject linkage, and inclusion criteria.
Proposes and invokes
Checksum and format checks, signal QC, electrode/anatomy registration inspection, and missingness analysis through tested workers.
Produces
PatientCase, QCReport, derivative manifests, excluded-case reasons, and repair requests.
Acceptance
Patient IDs, recordings, units, coordinates, transforms, channels, and annotations are coherent.
Boundary
Preserve raw data. Evaluation masks and outcome labels remain outside modeling access; linkage metadata are scoped separately.
R3 / VIRTUAL-PATIENT AGENT

Represent plausible explanations of the patient.

Consumes
QC-passed case, extracted methods, presurgical observations, hypotheses, and frozen fitting partitions.
Proposes and invokes
Select qualified model families, maintain competing network hypotheses, fit parameters, and test held-out model predictions.
Produces
Versioned ModelBundle ensemble, observation model, executable-environment manifest, diagnostics, and model-repair needs.
Acceptance
Numerical checks, recovery/identifiability tests, and predictive criteria match the declared intended use.
Boundary
A fitted virtual patient remains a model with uncertainty. A generic template is labeled explicitly if used for a permitted sensitivity analysis.
R4 / INTERVENTION-DESIGN AGENT

Define feasible scenarios and useful next comparisons.

Consumes
Qualified model ensemble, presurgical constraints, allowed intervention classes, objective definitions, and candidate budget.
Proposes and invokes
Generate surgery or stimulation scenarios; request physical-model checks; refine uncertain comparisons with fresh validation samples.
Produces
InterventionScenarioSet, feasibility reports, SimulationRequests, Pareto comparisons, and targeted follow-up needs.
Acceptance
All parameters, geometry, constraints, baselines, uncertainty sampling, and stopping rules are explicit.
Boundary
Surgery and stimulation use separate worker contracts. Changing a disease-model parameter is not itself a realizable treatment protocol.
R5 / INDEPENDENT-EVALUATION AGENT

Determine what the results support.

Consumes
Frozen protocol, versions, simulation records, review criteria, and explicitly authorized evaluation artifacts.
Proposes and invokes
Request independent reruns, robustness tests, source checks, and the separate blinded historical-outcome evaluation task.
Produces
SimulationComparison, OutcomeEvaluation, ValidationReport, failure examples, abstentions, and structured revision needs.
Acceptance
No leakage; patient-level metrics and uncertainty are correct; claims resolve to the appropriate evidence kind.
Boundary
The evaluator does not rewrite the frozen model after seeing test outcomes. Outcome-vault reveal is logged and controlled by the evaluation service.
R6 / IMPROVEMENT AGENT

Turn recorded failures into testable proposals.

Consumes
Authorized development-run artifacts, structured failures, review feedback, resource traces, and released method versions.
Proposes and invokes
Diagnose recurring issues and propose scoped changes to methods, tools, scheduling, prompts, or tests.
Produces
ImprovementProposal with evidence, exact change, anticipated benefit, offline benchmark, risks, acceptance checks, and rollback.
Acceptance
A proposal is benchmarked against its parent version, independently reviewed, and linked to a ReleaseRecord.
Boundary
Cannot update the active study, promote its own change, or reuse an exposed test cohort as fresh independent evidence.

06 / The first literature-to-dataset-to-virtual-surgery workflow

From a paper to a defensible comparison.

This is the first path through the research graph. It asks whether a published virtual-resection method can be reproduced and whether a frozen version informs observed outcomes on held-out cases. At every stage, unresolved prerequisites generate scoped needs; the controller routes repair and resumes only when the relevant checks pass.

Two tracks keep the evidence honest. A reproduction track can use published labels and delivered surgical masks to recover a known result. A separate evaluation track freezes the method and candidate-generation rules before access to test outcomes or postoperative intervention masks.

Task typeWhat it testsOutcome access
Simulation comparisonNumerical validity, feasible-candidate benefit, burden, uncertainty, and ranking stability across qualified models.Uses frozen presurgical model inputs and simulation results.
Historical-outcome evaluationAssociation between frozen predictions and observed outcomes for delivered interventions.Reserved masks and labels are revealed in logged stages to the authorized evaluation service.
0
Study controller + scientific lead

Write the protocol and define “success.”

Start with retrospective focal epilepsy surgery. Define eligible recordings and anatomy, the surgical intervention classes, a reproducible baseline, a model-level endpoint, and a clinical-outcome endpoint. A reasonable initial target to assess for feasibility is strict seizure freedom at a prespecified follow-up of at least 12 months. Retain the source classification and distinguish auras, seizure types, follow-up windows, and medication changes.

Choose evaluation metrics and analysis rules before labels are revealed. If the available cohort cannot support the desired endpoint, revise the protocol transparently before evaluation and record why.

Output: StudyProtocol v1, eligibility specification, endpoint dictionary, label-access policy, and configurable compute limits.
G0 / protocol ready: all required scientific decisions are explicit; development and evaluation roles have separate access; unspecified performance targets cannot be chosen after test results are seen.
1
Evidence and dataset scout

Search studies, methods, and associated datasets.

Search PubMed and relevant repositories for virtual resection, computational epilepsy surgery, patient-specific seizure models, and validation studies. Follow data-availability sections and citations to actual repository records. Keep the full query, date, result IDs, pagination, inclusion decisions, and excluded-study reasons.

G1 / evidence traceable: included records have valid source identities; every claimed dataset link has a supporting passage or repository record; unknown access remains unknown.
2
Evidence scout + case-curation agent

Verify which files support which questions.

Inspect repository metadata and permitted sample files. Confirm subject linkage between recordings, anatomy, electrode localization, intervention records, and outcomes. Check whether multiple papers use the same patients. Record access and reuse conditions before acquisition.

The EpiVR-associated study is a concrete seed for Lane A. Its primary publication reports shared electrophysiology and pre/post-resection imaging; current access, linkage, and usable contents still need verification. [2] The VEP paper is a methodological seed for Lane B; its published cohort does not itself establish access to patient files. [3]

Output: versioned DatasetCards, verified file inventory, access ledger, cohort-overlap assessment, and ranked eligible datasets.
G2 / acquisition eligible: actual available modalities support the proposed task; use conditions permit processing; missing intervention/outcome linkage prevents an outcome-validation claim.
3
Case-curation agent + retrieval worker

Acquire a small authorized pilot and create case manifests.

Retrieve only the files required by the selected protocol. Use resumable downloads, checksums, and a frozen inventory. Preserve raw files read-only; write derivatives under a run-specific directory. Use a small development pilot to measure real runtime and identify format problems before expanding acquisition.

Separate postoperative masks and outcomes into an evaluation store. Match records through stable pseudonymous subject IDs; uncertain matches become review items. Record actual usable subjects and reasons for every exclusion.

Output: retrieval manifest, PatientCase drafts, outcome/intervention linkage tables in the evaluation store, and a pilot resource profile.
G3 / files coherent: checksums match, identities and sessions link consistently, raw data remain intact, and the modeling role cannot read restricted evaluation labels.
4
Independent evaluator + study controller

Freeze the cohort split and prevent leakage.

Assign entire patients to development and test groups; account for center and overlapping published cohorts. Within each patient, specify which seizures or time periods are used for fitting and which are used for predictive checks. Keep overlapping windows and repeated sessions in their appropriate groups.

Use development subjects for pipeline repair and threshold selection. If the cohort is too small for a stable independent holdout, prespecify patient-level nested resampling and describe the resulting evidence as exploratory. Seek an independent cohort for later confirmation.

Output: CohortSplit with a saved seed or deterministic assignment rule, hashes, subgroup counts, and label-access records.
G4 / split locked: no subject or known cohort-family leakage; choices that use labels occur inside training folds; later protocol changes create a new study version.
5
Case-curation agent + tested preprocessing workers

Prepare signals and anatomy with visible quality checks.

Read recordings with a version-pinned electrophysiology adapter. Validate sample times, units, channel types, reference montage, dropped segments, bad channels, seizure annotations, and stimulation artifacts. Apply the published baseline’s preprocessing first; evaluate changes as separate variants.

Where anatomy is available, inspect imaging registration, contact coordinates, tissue assignments, and any derived network mapping. Store the transform chain and units. Use BIDS-compatible organization where appropriate; BIDS-iEEG explicitly represents electrode positions and their coordinate system. [7]

Output: QC-passed derivatives, electrode/channel map, optional anatomical reconstruction, and a report containing exclusion and uncertainty flags.
G5 / case ready: all required units, frames, references, dimensions, and linkage checks pass; unresolved critical registration or annotation problems halt affected analyses.
6
Virtual-patient agent + baseline worker

Reproduce a published virtual-resection method.

Implement the selected publication’s network definition, time windows, connectivity estimator, graph transformation, and outcome-analysis procedure. For an EpiVR-style baseline, begin with the corresponding contact-level network and declared virtual-removal calculation. Preserve distinctions between graph perturbation and a dynamical seizure simulation.

In the reproduction track, compare intermediate arrays and reported aggregate results wherever reference data are available. Pin the source revision, dependencies, estimator details, and numerical tolerances. Port legacy code with a parity test rather than assuming that newer packages preserve behavior.

Output: BaselineModelBundle, reproduced intermediate metrics, parity report, deviations log, and a frozen implementation.
G6 / baseline established: numerical differences fall within prespecified, justified tolerances or are explained. Missing reference data limit the claimed reproduction level.
7
Virtual-patient agent · conditional extension

Fit a patient-specific dynamical ensemble.

If Lane B inputs are verified, add TVB/Epileptor and a separately versioned inference adapter. Define how latent regional activity produces recorded SEEG/ECoG signals, including contact geometry and montage. Fit only permitted presurgical observations.

Check parameter recovery on synthetic cases, inference convergence, identifiability, and prediction of held-out seizure timing/spread summaries. Compare multiple initiation/network hypotheses and implementation families where practical. A good waveform fit is one check; intervention response needs additional evidence.

Output: validated ModelBundle ensemble, posterior-predictive checks, observation-model definition, and uncertainty inventory.
G7 / model qualified: the model meets the protocol’s declared use criteria. Missing inputs or inadequate predictive behavior keep this branch incomplete while the eligible baseline lane can continue.
8
Intervention-design agent + numerical workers

Generate and compare candidate interventions.

Generate candidates from presurgical evidence and a prespecified anatomical search space. Include the clinical presurgical plan as a comparator when it was genuinely available before intervention. Represent resection, ablation, and disconnection with explicit geometry and separate mapping rules.

Compare a no-intervention baseline and matched-burden controls. Sample model uncertainty, initial states, and relevant geometry perturbations. Evaluate seizure-related benefit, intervention burden, and available functional-risk proxies. Preserve a Pareto set: candidates for which improving one objective requires worsening another.

Output: SurgeryPlanSet, paired SimulationBatches or graph perturbation runs, feasibility results, uncertainty summaries, and stable/unstable ranking labels.
G8 / comparison credible: candidates are feasible under declared constraints, numerical checks pass, comparison budgets are matched, and conclusions survive the prespecified robustness tests or explicitly abstain.
9
Independent evaluator + outcome service

Evaluate observed outcomes without changing the model.

Freeze all candidate-generation and prediction rules. The evaluator then unlocks delivered intervention masks to score the intervention that actually occurred with the fixed method, followed by clinical outcomes. If a preoperative plan was available, evaluate that information source separately from postoperative ground truth.

Assess patient-level discrimination, calibration when probabilistic predictions exist, uncertainty intervals, and subgroup failures. Estimate intervals by resampling patients rather than treating many windows or simulated seeds as independent patients. Report incomplete follow-up and original outcome categories.

Interpretation: observed outcomes test the delivered interventions. They do not establish the clinical outcome of alternative unperformed candidates. Such alternatives remain hypotheses for subsequent validation.

Output: locked ValidationReport, patient-level results, failure analysis, comparison with baselines, and an explicit evidence-strength statement.
G9 / evaluation honest: no post-unblinding tuning enters the claimed test result; exploratory follow-up creates a new analysis version and is labeled accordingly.
10
Study controller + dossier builder + clinical / engineering review

Export a complete research package.

Produce a readable case/cohort dossier with data readiness, model assumptions, comparison results, maps, uncertainty, failures, and missing evidence. Include source references and a machine-readable manifest linking the computations. Make unsupported rankings or unavailable clinical-outcome probabilities visibly unavailable.

Clinical and engineering review produces a structured ReviewDecision. Accepted reports move to the release-policy check. Revision requests identify the affected artifact and stage; the controller invalidates descendants and reruns the necessary work. Authorized failures and review findings also become inputs to the separate improvement lifecycle.

Output: DecisionBundle, standalone HTML report, tabular results, manifests, and an authorized reproducibility archive.
G10 / release ready: the report matches the recorded data and validation status, limitations are visible, and the release policy permits the exported content.

07 / Match the model to the intervention question

Build complexity in evidence-backed steps.

Start with a reproducible network baseline. Add patient-specific dynamical inference when the inputs and validation support it. Treat stimulation as a separate physical and physiological modeling problem.

Model layerRole in the systemRequired validation
Published network baselineCompute the selected publication’s network features and virtual-removal effects. Provides a reproducible reference for more complex methods.Parity with reference calculations; sensitivity to preprocessing, network estimation, recording coverage, and outcome definition.
TVB / EpileptorModel regional seizure dynamics and propagation over a declared network. TVB documents an epilepsy simulation workflow. [5]Solver checks; synthetic recovery; observation-model checks; held-out seizure behavior; sensitivity to network and initiation hypotheses.
Bayesian patient inferenceInfer plausible spatial and dynamical parameters and retain uncertainty. BVEP offers relevant probabilistic inference implementations. [6]Convergence or approximation diagnostics; parameter identifiability; posterior-predictive checks; sensitivity to priors and misspecification.
Stimulation field modelMap geometry and device settings into electric-field or pathway effects. OSS-DBS is a candidate for DBS-specific modeling. [8]Mesh/solver convergence, boundary and unit checks, electrode geometry, tissue assumptions, and appropriate reference or measurement comparisons.
Neural-response / control modelMap stimulation effects to regional or cellular responses and network behavior. Select a reduced or detailed model according to the hypothesis and available data.Prediction of held-out recorded responses; state dependence; stimulation artifact handling; latency; generalization across settings.

Define surgical candidates in anatomical space.

Store each intervention as a geometry object with a coordinate frame, transform chain, uncertainty representation, and intervention type. A resection removes specified tissue and its modeled connections. A disconnection modifies specified pathways while retaining tissue. An ablation requires an explicit mapping from the affected volume to modeled tissue and connections.

Map the intervention into the model at the resolution the data support. Verify partial-parcel effects and uncertainty near boundaries. A node-level perturbation can be a useful approximation; record that approximation and test whether conclusions change at plausible alternative mappings.

Apply anatomical feasibility and available functional constraints before ranking. When language, memory, motor, visual, vascular, or tract information is missing, restrict the claim to the quantities actually measured. A network-derived risk proxy is not a measured postoperative functional outcome.

Optimize a declared set of tradeoffs.

Use seizure-specific endpoints alongside tissue/intervention burden, physiological-activity checks, and functional-risk estimates. Inspect the Pareto set before choosing any weighted score. Set objective definitions and weights before looking at evaluation outcomes.

Avoid a misleading success signal: low global signal variance can reflect broad suppression, numerical failure, or recording blanking. Require seizure-specific checks and valid residual physiology. An optimizer must not earn a better result by making the modeled recording disappear.

Technical design · robust comparison and stopping rules

For candidate a, model/hypothesis m, parameter draw θ, and initial state s, compute paired differences between the intervention and no-intervention run. Keep seeds and states matched where the engine permits.

For each eligible case:
  load frozen model ensemble and candidate-generation rules
  validate candidate geometry and constraints
  for each hypothesis / parameter / state sample:
    run baseline and candidate with paired conditions
    verify numerical and observation-model validity
    save seizure-specific metrics and burden / risk proxies
  summarize distributions and model-family disagreement
  compute Pareto set and ranking sensitivity
  expand only decision-relevant uncertain comparisons
  stop at prespecified precision / stability OR resource limit
  emit supported comparison OR incomplete / abstained status

Report mean or median benefit together with a conservative tail/risk measure if specified by the protocol. Explain whether uncertainty comes from patients, model parameters, seeds, geometry, or model families. Do not interpret simulated replicates as independent clinical observations.

Candidate search and validation use different simulation samples where possible. Final checks on fresh seeds/parameter draws reduce selection of candidates that exploit random simulation noise.

The research system proposes and evaluates offline candidates. Any future clinical programming or intervention would require a separately validated workflow with the responsible clinical team. This plan contains no patient-specific surgical target or stimulation prescription.

08 / Learning as an offline scientific experiment

Improve future runs through tested changes.

The improvement agent analyzes recorded failures and reviewer feedback, then submits a proposal. An independent validation process tests the proposal against the parent version. Promotion creates a new release for a subsequent study.

Use ScienceClaw’s memory as a source of hypotheses.

The existing PrincipleExtractor synthesizes patterns from prior investigation summaries and stores them in the knowledge graph. For this system, keep such outputs explicitly provisional: an extracted pattern becomes an ImprovementProposal or scientific hypothesis linked to source artifacts, with a declared population and test. It does not become an accepted clinical rule merely because it recurs in agent summaries. [12]

Initial “learning” can mean better extraction, tool adapters, model selection, experiment scheduling, or prompts. Automatic model-weight training is optional future work and requires its own training data, objective, benchmark, and release process.

Promotion checks: evidence traceability, meaningful improvement on the prespecified development benchmark, no unacceptable regression in required invariants, matched resources, independent review, and a reproducible rollback. Scientific acceptance criteria depend on the change and are fixed before the relevant test is examined.

Evaluation independence: once a reserved test cohort has influenced proposal design, mark it exposed for that development lineage. A future claim of independent generalization needs a fresh reserved cohort or a clearly separated, prespecified evaluation process. Repeatedly optimizing against one public benchmark does not create repeated independent validation.

Freeze behavior: a release never mutates an active study. An urgent correction halts affected work, records why prior results are invalid or stale, and starts a new version with the required revalidation.

09 / Evaluate software, models, and the research team

Three different kinds of validation.

Software correctness establishes that calculations and records behave as intended. Model validation tests predictive behavior. Clinical-outcome evaluation tests whether the recorded predictions relate to observed patient outcomes. Each needs its own evidence.

LEVEL 1

Software and contracts

Capabilities, units, coordinates, dimensions, task status, access boundaries, dependencies, artifact integrity, and repeatable numerical operations.

LEVEL 2

Model behavior

Reproduction, synthetic recovery, identifiability, held-out signal/propagation predictions, perturbation response, and uncertainty sensitivity.

LEVEL 3

Observed patient outcomes

Frozen patient-level evaluation, calibrated predictions where justified, follow-up definitions, independent cohorts, and functional-outcome limitations.

Threshold policy: engineering invariants are mandatory. Scientific tolerances and primary performance criteria are justified using the selected method, reference precision, development data, and intended use, then frozen before evaluation. The plan intentionally does not invent a universal “accuracy required for surgery” threshold.

Technical design · independent evaluation and statistical limits
  • Use whole-patient resampling for patient-level outcome intervals. State the number of centers and independent cohort families.
  • Fit feature selection, imputation, thresholding, and calibration inside training folds. Keep site-specific sensitivity analysis explicit.
  • Separate complete-case results from missing-data sensitivity analyses. Never count excluded cases as successful predictions.
  • If model outputs are uncalibrated scores, report them as scores. Fit a clinical-outcome calibration model only within the designated training process and validate it separately.
  • Predefine handling of censoring, unequal follow-up, endpoint-category differences, and subsequent interventions.
  • Use the delivered surgery for observed-outcome validation. Compare unperformed alternatives as model-based counterfactual hypotheses with explicit limits.
  • For stimulation, historical programming choices may be confounded and may cover only a narrow setting range. Check support/overlap before claiming an off-policy benefit.

The first five working days

  1. Freeze the starting point: pin ScienceClaw and write the initial study question, endpoint definitions, scope, and failure policy.
  2. Define the contracts: implement AgentProfile, TaskSpec, DatasetCard, and the artifact envelope; write capability, array-preservation, and scope tests.
  3. Close the publication path: configure private storage and test all outbound channels; introduce an injectable run root.
  4. Establish evidence acquisition: reproduce a logged search, extract the seed studies’ data-availability records, and start the access/completeness register.
  5. Run a synthetic case through the skeleton: submit, checkpoint, interrupt, resume, validate, and export one traceable result. Use the first verified real dataset only after eligibility and access checks.

First review milestone: a verified dataset register, one documented acquisition path, and a reproducible baseline run with complete provenance. This gives the team a concrete basis for choosing which patient-model and stimulation extensions are justified.

11 / Make reruns and failures ordinary

A small runtime that can grow.

Keep the initial deployment simple: one authoritative coordinator, a transactional job/index store, and separately managed numerical workers. Scale after the workflow and scientific contracts are stable.

Use event-driven repairs and scoped discovery.

A worker completion, gate failure, accepted fulfillment, stale artifact, or ReviewDecision creates a durable event. The controller updates only the affected tasks and exposes eligible needs to the right roles. Heartbeats supervise leases and run bounded evidence updates; they do not replace dependency-driven dispatch.

A newly discovered paper may justify a new method or prior. Record it as a proposed branch or future protocol update. Frozen evaluation runs retain their original scientific choices, with a visible record of later evidence.

Prototype deployment

Use a single coordinator with a durable SQLite job/index database and a controlled local worker pool. Store large data on a permissioned filesystem or object store. Numerical engines use pinned environments; a separate environment can support legacy-baseline reproduction.

A single coordinator owns leases and commits. Use transactions and crash recovery. Do not run multiple scheduler replicas against a single-process design.

Distributed deployment

Introduce a PostgreSQL-backed task/index service and a suitable queue or cluster adapter before using multiple schedulers. Preserve idempotent task keys, access scopes, job heartbeats, and atomic artifact commits.

A web app can display progress and reports. The domain runner remains authoritative for the scientific state machine.

Record enough to reconstruct every result.

Save raw-file checksums, selected derivatives, input manifests, source/code commits, dependency locks or container digests, solver options, parameter samples, seeds, candidate definitions, metrics, and gate verdicts. Record concise scientific rationales and decisions. Keep secrets and restricted raw content out of generic logs.

Use content-aware cache keys. Reuse a result only when data, preprocessing, hypothesis, model/solver configuration, implementation, environment, and relevant randomization agree. A changed upstream artifact creates a new version and marks dependent results stale.

Job identity: hash the task schema/version, actual input hashes, code/environment identifiers, scientific configuration, and seed specification. Use a separate attempt ID for retries. Commit outputs once per successful task identity, after validating files and manifest.

Resource policy: require configured concurrency, CPU/GPU time, storage, and model-token limits. Estimate pilot cost from measured runs. Cost overruns trigger a visible incomplete result or a pending resource decision; the system does not silently expand its budget.

Useful run events: task proposed, task admitted/rejected, job submitted/running, checkpoint saved, output committed, gate passed/failed/indeterminate, artifact stale, candidate infeasible, missing data, and export produced. These events should be understandable in the review interface.

Keep the finished report understandable.

  • Start with the question, available data, and what was actually tested.
  • Show a patient-specific map only when coordinates and registration support it; label the space and uncertainty.
  • Separate observed measurements, fitted estimates, simulations, and clinical outcomes.
  • Explain each candidate’s expected model benefit, burden, constraints, and ranking stability.
  • List contradictions, excluded cases, unavailable information, and model failure examples.
  • Provide one reproducibility manifest and clear links to inspect the underlying records.
12 / A shared vocabulary

Plain-language glossary.

Agent
A software role that uses a language model and permitted tools to carry out bounded research tasks.
Worker
A program that performs a defined operation such as filtering a recording, fitting a model, or running a simulation.
Artifact
A saved scientific or computational record with its inputs, origin, versions, and validation status.
Data contract
Rules describing what a record contains and what its fields mean, including units and patient context.
Gate
A required check that determines whether the workflow can advance to its next stage.
Provenance
The traceable history of the sources and calculations that produced a result.
iEEG / SEEG / ECoG
Intracranial EEG; recordings from depth electrodes (SEEG) or electrodes on the cortical surface (ECoG).
Connectome
A representation of connections between brain regions, estimated using a specified method.
Observation model
The mapping from hidden activity in a brain model to the signal the recording system would measure.
Epileptogenic network
A hypothesis about regions and connections involved in generating seizures. It is not identical to every region with an abnormal recording.
Virtual resection
A computational test that changes a model to represent tissue removal or disconnection, then measures the modeled effect.
Model ensemble
A collection of plausible models, parameters, or assumptions used to assess how conclusions depend on uncertainty.
Posterior
An updated distribution of plausible parameter values after combining a model, prior assumptions, and data.
Identifiability
Whether the available measurements distinguish between different model parameters or explanations.
Held-out data
Measurements excluded from development or fitting so they can provide a less biased check.
Leakage
Information from evaluation data entering model development, making performance appear better than it would be on new cases.
Pareto set
Candidates for which improving one objective requires worsening another, such as seizure control versus tissue burden.
Calibration
Whether a predicted probability agrees with how often the outcome actually occurs in comparable evaluated cases.
CCEP
A cortico-cortical evoked potential: a recorded brain response following electrical stimulation, potentially useful for testing network-response models.
Abstention
An explicit result that the available evidence does not support a reliable ranking or conclusion.
Scoped need
A request for a specific missing input or result, with patient, study, version, and acceptance rules.
Task lease
A temporary claim on a task that prevents duplicate execution and allows recovery if a worker stops responding.
Virtual-patient bundle
Patient-model hypotheses, parameters, uncertainty, measurement mapping, and software/environment versions saved together.
Release record
A reviewed, reproducible version of the system or method that can be selected by future studies.
